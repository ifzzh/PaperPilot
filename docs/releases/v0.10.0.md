# PaperPilot v0.10.0

PaperPilot v0.10.0 adds durable translation workflows, a Simplified Chinese default interface, personalized Daily arXiv selection, and self-service password changes.

## Highlights

- Translation jobs are persisted per user and dispatched fairly to the single isolated BabelDOC Worker. The new task center shows structured stage progress, queue position, heartbeat, readable events, and raw logs, with SSE updates and polling fallback.
- Paused, interrupted, and network-failed jobs can be resumed or retried. A task-local BabelDOC cache is isolated by owner, PDF digest, model, languages, and translation configuration and expires after seven days. Resume re-parses the document but reuses completed translation fragments; it is not an exact PDF-page checkpoint.
- The default interface language is Simplified Chinese while product terms such as Daily arXiv, Reading List, PDF, API, LLM, MinerU, BabelDOC, GitHub, and Markdown remain in English. User-facing dates are `YYYY-MM-DD`, and date-times are `YYYY-MM-DD HH:mm`.
- Daily arXiv defaults to 24 papers across three editable research topics with 12/8/4 target quotas, global arXiv-ID deduplication, local relevance gating, and LLM-failure fallback. Generic `LLM` or `Agent` mentions alone do not qualify a paper.
- PDF metadata and artifact state are separate. Verified first-page thumbnails are preferred; unavailable assets use themed gradient covers and expose a manual retry action with bounded backoff.
- Every authenticated user can change their password from Settings. Passwords are 8–128 characters; a successful change retains and rotates the current session and revokes other sessions.

## Offline migration

Stop all three services and back up SQLite and the paper directory. Preview and apply the additive workflow migration using the current user's Daily arXiv settings file:

```bash
python -m paperpilot.migrations.v010_workflows \
  --db /app/db/paperpilot.db \
  --settings /data/papers/.users/<user-uuid>/daily_arxiv_settings.json \
  --dry-run

python -m paperpilot.migrations.v010_workflows \
  --db /app/db/paperpilot.db \
  --settings /data/papers/.users/<user-uuid>/daily_arxiv_settings.json \
  --backup-dir /backups/paperpilot/v0.10.0 \
  --apply
```

The migration uses the SQLite backup API, keeps existing translation records (including AutoSci), adds topic/candidate and structured translation-event storage, and does not move PDFs. Roll back while the application is stopped:

```bash
python -m paperpilot.migrations.v010_workflows \
  --db /app/db/paperpilot.db \
  --settings /data/papers/.users/<user-uuid>/daily_arxiv_settings.json \
  --rollback /backups/paperpilot/v0.10.0/<manifest>.json
```

## Deployment

Deploy the Web, translation Worker, and Document Worker at v0.10.0 together and pin all three registry digests in production Compose. Only `127.0.0.1:7191` is exposed. No new secrets or public Worker ports are introduced.

Strict blocking CSP, removal of legacy inline handlers, and remaining CDN self-hosting are deferred to v0.11.0.
