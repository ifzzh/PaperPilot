# PaperPilot v0.10.5

PaperPilot v0.10.5 repairs the translation execution and log-viewing path.

Translation Worker now prepends its trusted application root to the BabelDOC subprocess `PYTHONPATH`, so the structured runner remains importable after the subprocess changes into an isolated job directory. A non-zero BabelDOC exit produces the stable `babeldoc_failed` code while the exit status and sanitized diagnostics remain in task events.

The Web UI keeps a separate latest-persisted-task index for every paper. Active tasks still control queue deduplication, but completed, failed and cancelled task UUIDs remain available for historical logs. Legacy `babeldoc_failed:<exit>` records receive the same Chinese explanation. The five tasks affected before this release remain failed and are not automatically retried.

Starting with this release, PaperPilot versions and component image versions are intentionally decoupled. Only components whose code, dependencies, runtime configuration or protocol boundary changed receive a new image. The committed compatibility matrix and the published Release record the complete tested digest set. Security gates still scan every image in that set.

There is no database or paper-storage migration. Back up SQLite, replace only the Web and Translation Worker digests, keep the Document Worker digest above, and restart all services. Existing failed translations can then be inspected and retried manually from the task center.
