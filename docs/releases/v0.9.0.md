# PaperPilot v0.9.0

PaperPilot v0.9.0 replaces Supabase email authentication with local usernames, Argon2id passwords, one-use administrator invite codes, CSRF-protected cookie sessions, and complete per-user ownership.

## Highlights

- Local username/password login; no email address or third-party identity service is required.
- The bootstrap administrator must change the temporary password at first login.
- Papers, categories, files, chats, reading data, settings, search indexes, jobs, and encrypted AI credentials are isolated by user UUID.
- Administrators manage users, invitations, password reset codes, and public HTTPS AI Providers from the browser without restarting PaperPilot.
- Private, loopback, link-local, reserved, and cloud-metadata destinations remain unavailable to browser-managed Providers.

## Required upgrade

This release changes the database and paper layout. Stop v0.8.2, back up SQLite and the complete paper tree, create the bootstrap administrator through hidden interactive input, then run the tenant migration `--dry-run` followed by `--apply`. The generated manifest supports `--rollback`.

Existing data is assigned to the selected bootstrap administrator and moved below `.users/<user-uuid>/`. PaperPilot refuses to start when it detects a legacy, mixed, or interrupted layout.

## Security boundary

The Web service remains bound to `127.0.0.1:7191` by the maintained Compose file. Translation and Document Workers retain their isolated mounts, non-root users, private ports, and resource limits. Strict blocking CSP, remaining inline-event removal, and self-hosting of the remaining CDN resources are planned for v0.10.0.

The Web image no longer contains MinerU, BabelDOC, PyMuPDF, pypdf, or rdflib. Document parsing remains confined to the Document Worker, while BabelDOC remains confined to the Translation Worker.

## Verification

- 184 non-integration tests and 75 subtests passed both locally and in the clean release image.
- Frontend content-safety tests passed 4/4.
- `pip-audit` reported no known vulnerabilities in all four locked requirement sets.
- Trivy reported no HIGH or CRITICAL fixed vulnerabilities in the three final images, and no repository secret or Dockerfile misconfiguration findings.
- Production local-auth startup without an active administrator failed closed as required.

The immutable image digests, SBOMs, scan reports, deployment verification, and rollback backup identifiers are recorded in the published GitHub Release and local release history.
