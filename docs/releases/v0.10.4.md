# PaperPilot v0.10.4

PaperPilot v0.10.4 is the deployment hotfix for the v0.10.3 Daily arXiv asset queue release.

Gunicorn's restrictive process umask could remove group-write permission from Web-created Document Worker task directories even though the requested mode was `2770`. The distinct Worker UID then could not create its status file, causing `invalid_worker_response`. Web staging now explicitly applies `2770` to the job and work directories after creation. Worker output directories remain `2770` and validated files remain `0640`, so only the shared `projectshare` group can read, promote and clean task output.

The issue was found during the first formal v0.10.3 deployment. Services were stopped immediately and the v0.10.3 migration manifest was used to restore all 53 pre-existing retry records and their original retry counts. No Daily arXiv PDF was promoted by the failed deployment.

v0.10.4 otherwise contains the complete v0.10.3 persistent single-flight queue, LLM/asset separation, backoff semantics, Chinese states and Worker release behavior. Upgrade from v0.10.2 using the same `paperpilot.migrations.v0103_daily_assets` dry-run/apply command documented for v0.10.3, but deploy all three v0.10.4 image digests together. Roll back using the generated manifest and the three v0.10.2 image digests.
