# iPaper 1.2.0 — 双翻译阅读与来源定位

状态：发布候选，真实供应商验收和正式部署尚未完成。以下描述当前源码能力；通过最终门禁后补充发布提交、组件摘要与实际验收。

同一论文可保留 BabelDOC 纯译文/双语 PDF，并使用 MinerU 解析后的结构化原文、译文或双语内容。切换已有结果不创建任务；生成弹窗显示语言、独立模型、页码范围、缓存和预算。单块重译失败保留旧译文，部分成功可继续阅读。

结构内容按阅读顺序显示段落、公式、表格、图片及图注，按需加载。有效来源可以跳回原始 PDF 并返回结构位置。选区问答使用服务端验证的来源，只有实际进入模型上下文且被引用的编号成为链接；旧聊天不补造来源。

## 兼容与限制

- 现有原文、版式译文、账号、聊天、任务与原始/译文位置保留。新结果使用增量 `processing_*` 表和 owner 隔离不可变文件，没有第四个常驻服务。
- 独立结构模型仅在未配置时从 ifzzh 的 BabelDOC 设置由服务端初始化。密钥采用独立表和用途加密；旧镜像仍能读取其原有密钥表。
- Document Worker 先校验并按每段最多 200 页分段。当前输入总限额 2,000 页/100 MiB，结构任务默认 200 请求、50 万输入/25 万输出 token 保守预留及两小时；每请求 120 秒硬截止。超时或未确认请求不自动重发。
- 精确区域只来自已验证的 MinerU schema/页面变换；未知、旋转或裁剪等未验证转换降为页级，没有可靠页码则不跳转。BabelDOC PDF 不推断与原文逐页对应。
- 全局结构并发两个、每用户一个活动任务，等待队列 20。默认每结果 1 GiB、每用户 10 GiB；临时检查点 7 天、详细事件 30 天。旧结果、成功译文和引用不自动删除。
- 独立实现参考固定 PaperQuay 0.1.25 提交，未搬入 AGPL/Electron 代码。保留 PaperPilot/Resophy/PaperQuay 来源及原许可事实；KaTeX 为 MIT 依赖。

## 备份与回退

升级前检查活动任务，优雅停止写入，保存 SQLite 一致性快照、匹配不可变产物、完整论文树、受限配置和原主密钥。正式 Compose 固定三个版本摘要，保留现有 `deploy_document_jobs` external 卷、资产路径与 UID/GID，不使用 `down -v`。

回退恢复本次部署前的三镜像、配置与 Web latest，保留当前数据库及新增产物。旧镜像可继续写旧功能数据；再次升级读取保留的新结果。不得用旧库备份覆盖部署后新增用户数据。持久备份包含独立 `rollback.py`；不执行品牌改名时期的路径回退。操作详见[结构产物备份与回退](../operations/structured-backup.md)。
