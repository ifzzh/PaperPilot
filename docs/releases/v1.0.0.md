# PaperPilot v1.0.0 — P0 experimental workbench

This release completes the P0 integration foundation. The old homepage stays the default; authenticated users can open the experimental workbench when `PAPERPILOT_WORKBENCH_ENABLED=true`. P1's complete library is planned for 1.1.0; P2's complete reading workspace and M1 for 1.2.0.

## Included

- Same-origin React/TypeScript workbench with existing session/CSRF and owner isolation, real paper list/detail, pagination, logout and cross-tab state cleanup.
- Self-hosted PDF.js single-page reading, original/translated assets, selection, zoom/rotation, private file responses and existing single-paper chat history/streaming.
- MinerU archive compatibility: discard at most one strictly named top-level UUID origin PDF after path/type/size/count/ratio checks; never extract it. Enforce the 4 MiB JSON limit. Existing final cleanup still retains Markdown/images only.
- Fix chat persistence when OpenAI-compatible services append usage-only chunks with no choices.
- Fail closed when the pinned security scanner download or checksum verification fails; never execute an incomplete scanner.

## Components and deployment

Publish Web `1.0.0` and Document Worker `1.0.0-document-worker`. Reuse Translation Worker `0.10.5-worker@sha256:a7b4a90f214d8628e40c4aa7b919bb6ecb178835e40a10303450634d6b4b609c`. Registry digests and final test/security reports accompany the GitHub Release.

No database schema or asset migration. Back up SQLite consistently and preserve the deployment configuration/permissions. Set the workbench flag explicitly in the effective Compose environment. MinerU transfers require the exact origins `https://mineru.oss-cn-shanghai.aliyuncs.com,https://cdn-mineru.openxlab.org.cn`; no wildcard or private-address exception is added. Update Web and Document Worker together, retain internal Worker networking, and verify health/ready, existing assets and login after startup.

Rollback restores the previous Web 0.11.0 / Document Worker 0.10.4 digests and original configuration; Translation Worker remains unchanged. Do not restore an old database over new user writes for a code-only rollback. Setting the workbench flag false hides the experimental entry.

## Validation and limits

Release acceptance includes isolated Worker HTTP submission/manifest/output/cleanup of the saved synthetic MinerU archive; real model streaming, persistence, fresh-session retrieval and tenant isolation; frontend tests and browser light/dark desktop/mobile coverage; full Docker nonintegration tests and dependency/image/security scanning. Failed real-call attempts exposed and led to the usage-tail fix; only the successful post-fix run counts as acceptance. No new MinerU cloud task was created for release acceptance.

The workbench remains experimental: multi-paper tabs, persisted reading positions, thumbnails and selection-to-question belong to later stages. Stop receiving does not cancel a server model task. Rotation OCR/coordinate generalization and structural persistence remain P3 work. Whole-site inline-style remediation moves explicitly from the former 0.11.1 plan to 1.1.0/P1; script CSP remains strict. Existing CC BY-NC license / MIT classifier inconsistency is documented without changing legal terms; no PaperQuay code is copied.
